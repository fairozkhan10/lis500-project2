Quick definitions (plain language)

Implicit bias is when your brain makes quick associations automatically. The risk isn’t just “bad attitudes”— it’s when fast assumptions quietly shape decisions (hiring, policing, grading, health care, moderation, etc.).

Intersectionality helps explain why “bias” isn’t the same for everyone. People experience systems differently at overlapping identities (race/gender/class/disability, etc.), so checking only one category can hide real harm.

How to use this page

  1. Pick a “path” below (student / educator / technologist).
  2. Use the checklist to evaluate a tool or policy (not just read definitions).
  3. Bring one concrete example back to your other pages (so the site feels connected).

Pick your path (interactive)

Path A — If you’re a student (10–15 minutes)
  • Project Implicit: take an IAT — do it once, then write 3 sentences on what surprised you.
  • APA: overview of implicit bias — a grounded explanation of what it is (and what it isn’t).

Use case idea: connect your result to one tech system you’ve used (recommendations, search, ads, grading, etc.).

Path B — If you’re teaching / leading a group
  • APA: implicit bias resources — language you can use without shaming people.
  • NPR Code Switch — real stories that show how “systems” hit people differently.

Try: have your group identify one “default” in a tool (who it assumes, who it ignores).

Path C — If you’re building a tech system (product / data / ML)

The goal isn’t perfect neutrality—it’s checking impact, documenting assumptions, and creating ways to challenge outcomes.

  • Ask what’s missing from your dataset (who/what outcomes aren’t recorded).
  • Test across groups (don’t only report one overall accuracy metric).
  • Document decisions: what you optimized for, and what you chose not to.

Bias Check Toolkit (copy/paste checklist)

Use this when evaluating an app, policy, model, or “neutral” workflow.

If you check 2+ items, that’s not “failure”—it’s a sign your system needs documentation, testing, and accountability routes.

Connection back to Code & Power

A theme in this course is that tech encodes social power: it scales decisions, normalizes assumptions, and can make inequality look like “just the output.” Intersectionality matters because harm often compounds, and one-axis thinking can hide it.
